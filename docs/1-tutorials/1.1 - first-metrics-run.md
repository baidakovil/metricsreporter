## Tutorial: Produce Your First Metrics Reporter Dashboard

**Goal.** Clone MetricsReporter, collect coverage and code metrics on its own codebase, and open the generated HTML dashboard. Plan ~10 minutes on a clean machine.

### 1. Prerequisites

- .NET 8 SDK with `dotnet` available on `PATH`.
- **Roslyn metrics** — MetricsReporter reads Roslyn metrics XML but does not produce it. You need `Metrics.exe` from the [`Microsoft.CodeAnalysis.Metrics`](https://www.nuget.org/packages/Microsoft.CodeAnalysis.Metrics) NuGet package to generate `SolutionMetrics.g.xml`. This repo ships a prebuilt `win-arm64` binary in `build/Resources/metrics/win-arm64/`; on Windows x64 you must swap it — see [build/Resources/metrics/README.md](../../build/Resources/metrics/README.md). Coverage collection and the HTML dashboard work on any platform regardless.
- Git.

### 2. Clone and restore

```powershell
git clone https://github.com/baidakovil/metricsreporter.git
cd metricsreporter
dotnet restore
dotnet tool restore
```

`dotnet tool restore` reads `.config/dotnet-tools.json` and installs three local tools:
- `metricsreporter` — the MetricsReporter CLI itself
- `reportgenerator` — HTML coverage renderer
- `altcover` — OpenCover-compatible coverage instrumentation

### 3. Generate metrics (config-driven)

MetricsReporter eats its own dogfood — the repo already has `.metricsreporter.json` configured to analyse itself. Just run:

```powershell
metricsreporter generate
```

What happens under the hood:

1. The `scripts.generate` hook (`Metrics/scripts/prepare-metrics.ps1`) runs `dotnet msbuild` with Roslyn Metrics and SARIF targets enabled — producing `Metrics/Roslyn/SolutionMetrics.g.xml` and SARIF files under `Metrics/Sarif/`.
2. The CLI aggregates OpenCover XML, Roslyn XML, and SARIF inputs.
3. Thresholds from `Metrics/MetricsRules/MetricsReporterThresholds.json` are applied.
4. Baseline delta is computed against the previous run.
5. JSON and HTML reports are written to `Metrics/`.

> **Note:** Coverage collection runs separately via `Metrics/scripts/collect-opencover.ps1`. To include coverage data, run tests with instrumentation first:
> ```powershell
> dotnet test MetricsReporter.Tests/MetricsReporter.Tests.csproj `
>     /p:OpenCoverInstrumentationEnabled=true `
>     /p:OpenCoverCollectionEnabled=true `
>     /p:OpenCoverHtmlReportEnabled=true
> ```
> Then re-run `metricsreporter generate`.

### 4. Inspect the outputs

After a successful run you should see:

| Artifact | Path | Purpose |
| --- | --- | --- |
| `MetricsReport.g.json` | `Metrics/` | Canonical tree (Solution → Member) with metric values, deltas, suppression flags, and metadata. |
| `MetricsReport.html` | `Metrics/` | Interactive dashboard — use the filter box, detail slider, and awareness slider. |
| `MetricsBaseline.g.json` | `Metrics/MetricsTemp/` | Snapshot used for delta calculations on the next run. |
| `SuppressedSymbols.g.json` | `Metrics/MetricsTemp/` | Symbols decorated with `[SuppressMessage]`, linked to metric identifiers. |

Open `MetricsReport.html` in a browser. Try:

- **Detailing** — limit the deepest visible level without re-rendering the table.
- **Awareness** — show only warnings or errors; ancestors stay visible so you retain context.
- **Filter** — type a namespace prefix or rule ID; instant filtering even for large codebases.

### 5. Query metrics from CLI

```powershell
# Find the first coupling violation in the Aggregation namespace
metricsreporter read --namespace MetricsReporter.Aggregation --metric Coupling

# Check all branch coverage violations grouped by type
metricsreporter read `
    --namespace MetricsReporter.Processing `
    --metric OpenCoverBranchCoverage `
    --group-by type

# Verify a specific symbol passes thresholds
metricsreporter test `
    --symbol MetricsReporter.Aggregation.MetricsAggregationService `
    --metric Complexity
```

### 6. Next steps

- Customize thresholds in `Metrics/MetricsRules/MetricsReporterThresholds.json`.
- Try the AI refactoring prompts in `Metrics/Agent/` — hand one to your AI coding agent along with a namespace to fix.
- Read the [configuration reference](../3-reference/3.1%20-%20configuration-options.md) to wire MetricsReporter into your own project.
